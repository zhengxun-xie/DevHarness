# OKR 项目视图（OKR Project View）

> M5 新增：把看板之外的任务数据以完整 OKR 层级呈现。数据源是「系统软件组OKR管理」多维表格的**三张表**（O → KR → 任务 → 模块子任务），host 一次聚合，客户端成树，无额外请求。

## 1. 动机

数据源本名就是 OKR 管理：飞书界面里 O1 → O1KR1 → 移动子系统ROS2 2.0.0主线版本发布 → 底盘/定位/导航模块，是四层树。早期实现只读了任务表内部的「父记录 2」，仅渲染 任务 → 模块子任务 两层，丢失了 O 与 KR 两级——既不体现"这条任务服务于哪个 KR、哪个目标"，也看不到 KR 的自报进度。本设计补齐完整层级。

## 2. 数据层级（跨三张表）

```
O1: 中间件版本开发迭代和持续支持            🎯Objective 表  tblXtvkNiyPEvNef
 └─ O1KR1: 移动子系统ROS2发布（底盘/定位/导航）📈KR 表        tbl4NfvZx6Txxtc7
     └─ 移动子系统ROS2 2.0.0主线版本发布      📋任务表        tblKMr0kmSVq7Ibn
         └─ 底盘模块ROS2 2.0.0主线版本发布    📋任务表（父记录 2）
```

关联字段：

| 关系 | 字段 | 位置 |
| --- | --- | --- |
| O → KR | KR 表 `Objective（目标）` link | 📈 表 → 🎯 表 |
| KR → 任务 | 任务表 `KR（关键结果）` link | 📋 表 → 📈 表 |
| 任务 → 模块子任务 | 任务表 `父记录 2` link | 📋 表内 |

`state()` 三表并行拉取；实测 3 O / 19 KR（25 行去空）/ 91 任务，91 条任务全部关联 KR、19 KR 全部关联 O，零孤儿。

## 3. 树组装（buildTree）

组件只消费 DevTaskPanel 传入的已过滤 `tasks` + 全量 `objectives` / `keyResults`：

1. 任务按 `krId` 分组；`krId === null` 或 KR 不在可见集合 →「未关联 KR 的任务」末尾区；
2. KR 可见性：含 ≥1 条可见任务才成树（归属/周期过滤后自然收窄）；
3. O 可见性：含 ≥1 条可见 KR 才渲染；
4. 同一 KR 内再按 `parentId` 分出 任务 → 模块子任务；父任务被过滤的子任务作为独立任务行展示。

## 4. 每层的信息密度

```
┌────────────────────────────────────────────────────────────────────────────┐
│ ▾ O1: 中间件版本开发迭代和持续支持   谢郑勋  2026 H2  34 / 91  ▓▓▓░░ 37%      │  O 层：only owner/period/counts/derived progress
│   ▾ O1KR1: 移动子系统ROS2发布…      王胡森  20 / 20  59%  ▓▓▓░░ 40%          │  KR 层：badge=表内自报进度，bar=可见任务推导
│     ● 移动子系统ROS2 2.0.0主线版本发布   王胡森 09-11  进行中 40%             │  任务层：dot/title/owner/due/progress badge
│       ● 底盘模块ROS2 2.0.0主线版本发布   张军杰 09-30                        │  子任务层：dot/title/owner/due
└────────────────────────────────────────────────────────────────────────────┘
```

| 层 | 元素 |
| --- | --- |
| O | 折叠箭头、标题、负责人（≤3 +N）、目标周期徽章、`完成/总数`、可见任务推导进度条 |
| KR | 折叠箭头、标题、负责人、`完成/总数`、**表内自报进度徽章**（KR任务进度 "59.0%"→59%）、推导进度条 |
| 任务 | 状态点、标题（点击编辑）、负责人、截止日期、进度徽章（「任务进度」字段或子任务比例推导） |
| 模块子任务 | 状态点、标题（点击编辑）、负责人、截止日期 |

两种进度并存是有意的：**自报进度**是团队在表格里填的主观判断，**推导进度**是当前可见范围内任务完成的客观比例。周期/归属过滤只改推导值与计数，不动自报值。

## 5. 交互

| 操作 | 行为 |
| --- | --- |
| 点击任务/子任务标题 | 打开 `TaskEditDialog` 编辑该记录 |
| 点击 O/KR 行 | 只读：状态流转走看板或编辑弹窗；O/KR 表字段不提供写回 |
| 点击各级折叠箭头 | 展开/收起该层（默认全展开，aria-expanded 可及） |
| 拖拽 | 项目视图不支持（拖拽是看板列间语义） |
| 新建任务 | header「新建任务」→ Bitable 建任务，`krId` 为空 → 落入「未关联 KR 的任务」区 |

## 6. 与过滤器的关系

组件不感知过滤器，只消费 `filteredTasks`：

- **团队视角**：整棵树；无任务的 KR/O 不渲染；
- **个人视角**（如 王胡森）：只有含他任务的 KR/O 出现，计数与推导进度收敛到他的任务；KR 自报进度仍是团队值，可作对照；
- **周期**：任务按 `dueDate` 过滤后成树，无日期者保留；O/KR 骨架随可见任务自然收张。

## 7. 边界情况

| 情况 | 表现 |
| --- | --- |
| 任务 `krId` 为空 | 「未关联 KR 的任务」末尾区 |
| 任务 krId 指向已被删除的 KR | 同上，按孤儿处理 |
| KR `objectiveId` 为空 | 「未关联目标的 KR」末尾区（可折叠） |
| 过滤后范围内无任何可见任务 | 空态「当前范围内暂无 OKR」 |
| KR 无任务 | 不渲染（该 KR 没有拆解可展示） |
| 「任务进度」为 0–1 小数 | 取整百分比；>1 视为百分数原样取整 |

## 8. 性能与渲染

- `ObjectiveNodeRow` / `KrNodeRow` / `TaskRow` / `SubtaskRow` 均 `memo`：单节点折叠只重渲染自己；
- `buildTree` 以 `useMemo` 缓存，依赖 `[tasks, objectives, keyResults]`；
- 3 + 19 + 91 + 15 个节点一次性渲染，纯文本无测量开销，无需虚拟滚动。
